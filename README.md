# Conference Assistant

### От обсуждения проектных решений — к проверяемым нормативным основаниям

Интеллектуальный ассистент для анализа строительных совещаний, объединяющий распознавание речи, разделение участников и поиск по нормативной документации.

Conference Assistant преобразует аудиозапись в структурированную стенограмму, выделяет вопросы о проектных решениях и находит связанные положения СП и ГОСТ. Используя найденные фрагменты, языковая модель формирует обоснование со ссылками на документы и страницы, а программные проверки контролируют происхождение цитат и числовых значений.

В основе проекта — сочетание локальной обработки аудио, гибридного нормативного поиска и генерации с опорой на источники — Retrieval-Augmented Generation (RAG). Результат работы сохраняется в виде стенограммы, машиночитаемого анализа и отчёта, позволяющего проследить путь от реплики участника до нормативного основания.

Проект разрабатывается как исследовательский офлайн-прототип для поддержки принятия проектных решений. Он не заменяет профессиональную экспертизу: применимость требований и корректность итоговых выводов требуют проверки специалистом.

> В текущей версии возможны ошибки обработки ответов LLM. Найденные требования, условия их применения и выводы необходимо проверять самостоятельно.

## Технологии

Python, faster-whisper, pyannote.audio, PyMuPDF, sentence-transformers, ChromaDB и GigaChat API.

## Подготовка

Команды ниже предназначены для Windows и PowerShell и выполняются из корня проекта.

Создайте виртуальное окружение и установите зависимости:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Если окружение уже настроено, используйте существующую `.venv` без повторного создания и переустановки зависимостей.

Для ускорения локальных моделей рекомендуется NVIDIA GPU и совместимая сборка PyTorch с CUDA. На Hugging Face необходимо принять условия доступа к используемой модели pyannote.

Создайте в корне проекта файл `.env` (если он уже существует, используйте его):

```dotenv
HF_TOKEN=ваш_токен_Hugging_Face
SBER_ULTRA=ваш_ключ_авторизации_GigaChat
GIGACHAT_MODEL=GigaChat-3-Ultra
```

Не публикуйте `.env`, API-ключи и токены. Файл `.env` должен находиться в `.gitignore`.

## Подготовка документов

Поместите нормативные PDF с текстовым слоем в `data/documents/`, затем выполните индексацию:

```powershell
.\run-direct.ps1 -m rag.index
```

## Полный запуск

Поместите аудиозапись в `data/audio/` и запустите:

```powershell
.\run-direct.ps1 -m app.analyze_meeting data\audio\construction_meeting.wav --debug
```

Замените путь на свой аудиофайл. Результаты сохраняются в `data/results/`.

Launcher `run-direct.ps1` запускает Python из `.venv` в проектном Direct mode, не отключая VPN и не меняя сетевые настройки остальных приложений.

## Отдельные команды

Поиск по нормативным документам без LLM:

```powershell
.\run-direct.ps1 -m rag.search "требования к эвакуационным выходам"
```

Вопрос к RAG и GigaChat:

```powershell
.\run-direct.ps1 -m llm.ask "Какие требования предъявляются к эвакуационным выходам?" --debug
```

Продолжение прерванного анализа:

```powershell
.\run-direct.ps1 -m app.analyze_meeting --resume "data\results\<имя_файла>_progress.json" --debug
```

Локальные тесты без обращения к GigaChat:

```powershell
.\run-direct.ps1 -m pytest -q
```

Первый запуск может потребовать загрузки локальных моделей. Генерация ответов требует доступа к GigaChat API и расходует его квоту.
