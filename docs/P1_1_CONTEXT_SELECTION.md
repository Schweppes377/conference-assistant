## 4. Новый отбор

### 4.1. Глубина

Число запросов, их тексты, semantic TOP-20 + lexical TOP-20 на запрос, веса reranker и порог cosine 0,84 сохранены. Уже полученное объединение ранжируется прежним способом, но selector видит **до max(candidate_k, 40)** основных кандидатов. Допускаются прежние два дополнительных связанных chunks; максимум при настройках по умолчанию — 42.

Это не TOP-40 нового semantic поиска и не увеличение контекста LLM. Дополнительных запросов к E5/Chroma для расширения глубины нет. SOURCE_1–SOURCE_40 соответствуют порядку того же reranker; дополнительные SOURCE получают следующие номера. JSON trace показывает отдельно `initial_depth=20` и `internal_pool_depth=40`.

### 4.2. Аспекты и роли

Аспекты строятся из вопроса и технических search_terms без reference sources. Отдельные «уклон» и «ширина» связываются с ближайшим названным объектом. Разговорные формулировки не должны становиться самостоятельными аспектами. Пример полученных аспектов МГН: уклон пандуса, ширина пандуса, подъёмная платформа, доступность входа.

Роли для выбора:

1. `direct_requirement`: объект и запрашиваемый параметр встречаются совместно в нормативной фразе/таблице.
2. `mandatory_condition`: требуемая ссылочная зависимость выбранного положения.
3. `related_explanation`: дополнительный связанный текст, не распознанный как обязательное условие.
4. `general_context`: общий тематический контекст.
5. `service_or_irrelevant`: служебный либо не поддерживающий аспекты текст. Служебные фрагменты исключаются; эвристическая нерелевантность понижает приоритет.

Проверка учитывает ограниченную близость параметра к объекту, границы номерных пунктов и модальные формулировки. Упоминание объекта только в придаточном условии не приравнивается к основному предмету требования. В таблицах близость слов не применяется как к обычному предложению: заголовок и строки могут быть разнесены.

Есть прозрачные пространственные признаки «вход/наружный/внешний», «внутри/между этажами», «сцена/трибуна». Ссылочное положение может наследовать лишь диагностическую подсказку области от явно ссылающегося положения того же файла. SOURCE родителя и ссылка сохраняются; если подсказка нужна выбранному фрагменту, её основание учитывается в бюджете. Это не доказательство юридической применимости, и каждый role содержит `applicability_verified=false`.

Здесь нет правил по ISSUE, обозначениям СП, страницам, chunk IDs и контрольным нормативным числам. Лёгкая нормализация «уровень/уровни» и «лифтовая/лифтов» используется только для поиска совпадений.

### 4.3. Распределение пяти мест

- Сначала выбираются прямые требования, добавляющие новый аспект.
- Между такими кандидатами учитываются прежняя relevance, взвешенный прирост покрытия и качество лексического совпадения. Добавочные коэффициенты: 0,40 прироста и 0,20 совпадения; веса аспектов уменьшаются по порядку как `1/(1+0,15*i)`.
- Затем сохраняются обязательные ссылки/условия уже выбранных требований; оставшиеся места заполняются другими прямыми требованиями и общим/поясняющим контекстом.
- Для известных обязательных зависимостей резервируются оставшиеся места. Новое основание не включается, если оно вместе с обязательными зависимостями заведомо не помещается в оставшиеся слоты/символы.
- Общий бонус +1,0 для любого linked chunk удалён. Пояснение больше не обходит прямое требование только потому, что оно связано ссылкой.

Обязательность ссылки — консервативный локальный сигнал нормативной фразы либо перечня условий после двоеточия. Ссылка из соседнего номерного пункта не наследует объект другого положения. Существующий кандидат может оказаться обязательной зависимостью: дедупликация больше не скрывает такую связь. Нового рекурсивного обхода корпуса нет; рассматриваются ограниченные связи внутри имеющегося пула.

Целые тексты chunks не обрезаются; условия и исключения внутри выбранного chunk остаются. Новые причины отказа: `dependency_slots`, `dependency_budget`. Если зависимость всё же не удалось включить, она отражается в `missing_dependencies`. Содержимое требований и нормативная применимость не удостоверяются этим механизмом.

### 4.4. Диагностика и совместимость

В trace добавлены `selection_version`, роли/совпавшие аспекты/конфликты области, `candidate_links`, `required_by`, `uncovered_aspects`, `missing_dependencies`, описание метода покрытия и **`completeness_verified=false`**. Пустой список uncovered не означает экспертно доказанную полноту.

Контракты SourceEvidence/PreparedQuestion/QAResult и версия checkpoint не изменены. Необязательный retrieval_trace уже существовал в P1. Старый progress продолжает использовать свой сохранённый retrieval, без скрытого перерасчёта; старые SOURCE IDs и готовые ответы не перенумеровываются. Чтобы проверить именно новый selector, нужен явно новый prepare/анализ из сохранённых вопросов, а не resume уже подготовленного старого контекста.

### Стоимость

Прогретый поиск/подготовка восьми вопросов: P1 **3,745 с**, P1.1 **6,667 с**. Разница +2,922 с (около +78%). Подготовка существующего корпуса/кэша и cached E5: P1 7,295 с, P1.1 6,248 с отдельно. Сумма подготовки и восьми prepare: примерно 11,040 и 12,915 с.

## 7. Ограничения и рекомендация

1. **Нет независимой семантической экспертизы.** Совпадения, модальные слова, таблицы и spatial hints иногда дают ложные признаки прямого требования. Таблицы особенно сложны без отдельной структуры строк/колонок.
2. **Регрессии 002/003 реальны:** ухудшился приоритет специального/жилого основания, хотя все нужные источники ещё доступны LLM. Увеличение Hit не оправдывает уверенного вывода по первым общим положениям.
3. Строгая связь параметра с объектом может пропустить нормативную анафору («их высота») или синоним; общий контекст иногда остаётся полезным, но не становится доказанной нормой.
4. Выделение аспектов не полное: шум, синонимы и составные параметры требуют независимой разметки. Указанные 21/27 — не качество юридического ответа.
5. Ссылочные условия ограничены существующим пулом, двумя дополнительными chunks и локальным разрешением ссылок того же файла. Междокументная экспертиза и рекурсивный сбор не реализованы. Если основание с обнаруженными зависимостями не помещается, оно исключается с причиной, а не публикуется без известного условия.
6. Число кандидатов выросло, но корпус/модель/порог не менялись; отсутствие нужной нормы в первом объединении selector исправить не может.

**Критерий 004/006/008 выполнен без увеличения лимита контекста.** На этих примерах нет оснований автоматически менять 5/12000. На синтетическом ограничении атомарная группа корректно исключается и аспект остаётся непокрытым.

Рекомендуется следующий **явно разрешённый пользователем текстовый контроль RAG→GigaChat по сохранённым вопросам с ручной проверкой условий**, без повторного ASR/diarization. Полный запуск автоматически не выполнялся. Это готовность проверить новую генерацию, а не объявление системы полноценной нормативной экспертизой. Существующие P0-ограничения на подтверждение соответствия сохраняются. Приоритет 002/003 следует отдельно проверить в таком контроле; дополнительные улучшения не маскируются изменением эталона.

## 8. Артефакты и воспроизведение

- `P1_1_BASELINE.json` — точная копия зафиксированного P1.
- `P1_1_COMPARISON.json` — итоговый реальный локальный retrieval, contexts, provenance, trace и неизменённые reference metrics. Для совместимости поле `p1_prepared` содержит новый запуск; его версия `selection_version=p1.1-1`, а `previous_p1` — прежние агрегаты.
- `P1_1_COMPARISON.csv` — время, размер контекста и диагностическое покрытие по восьми вопросам.
- `P1_1_ASPECTS.json` — одинаковая эвристическая оценка аспектов на двух контекстах.
- `P1_1_PARAMETERS.json` — параметры/hashes перед окончательным запуском.
- `P1_1_TEST_RESULTS.json` — 194 локальных теста.
- `P1_1_EXPERIMENT_1.json`, `P1_1_EXPERIMENT_2.json` — промежуточные результаты, включая ухудшения. Исторические P1-файлы не перезаписаны.

Из корня проекта:

```powershell
.\run-direct.ps1 -m pytest -q --reliability-output=docs/P1_1_TEST_REPEAT.json
```

Повторение только локального retrieval (нужен новый output, прежний файл не перезаписывается):


Это вспомогательная копия индекса; если её перенести/удалить, потребуется новая копия существующего Chroma, не переиндексация. Сеть запрещена самим экспериментом, модель должна уже находиться в кэше. Сравнение проверяет hashes analysis/dataset/checkpoint; при другом наборе входов сопоставление с прежним P1 отклоняется.
